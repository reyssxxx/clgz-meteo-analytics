# Метеоаналитика — Центрально-Лесной заповедник

Веб-сервис для автоматической обработки данных метеостанций урочища «Красное»: вместо ручного
сведения сроков в Excel — суточные и декадные таблицы, графики, статистика, тренды и отклонения
от среднего за любой выбранный период. Кейс 02 «Умная аналитика метеоданных», Заповедный хакатон.

## Запуск

Нужен Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
uv run uvicorn meteo.api:app --port 8000
```

Откройте http://localhost:8000. Данные кейса (`data/clgz/`) загружаются при старте автоматически.

Через Docker:

```bash
docker build -t meteo .
docker run -p 8080:8080 meteo          # http://localhost:8080
```

Тесты и пакетная обработка без интерфейса:

```bash
uv run --group dev pytest
uv run python -m meteo.batch data/clgz --out reports --start 2025-01-01 --end 2025-12-31
```

## Что умеет

| Экран | Что показывает |
|---|---|
| **Обзор** | Выбранный период на фоне всех лет станции, отклонения по месяцам (тепловая карта), место периода среди тех же периодов других лет, короткие выводы текстом |
| **Таблицы** | Суточная таблица за месяц (сроки по каждым суткам, неполные сутки помечены, итоги по декадам, месяц, экстремумы) и декадная таблица за сезон/год/любой период. Выгрузка в Excel в том же виде |
| **Тренды** | Полосы потепления, тренд по году, сезону или месяцу (МНК, тест Манна–Кендалла, оценка Сена) — только внутри ряда одной станции |
| **Сравнение** | Два любых периода: годовой ход и разница с проверкой значимости |
| **Поляна и поле** | Кр1 против Кр2 (или любые две станции): разница по месяцам, средний суточный ход по часам, автоматическое предупреждение о вероятном сбое датчика |
| **Агроклимат** | Суммы температур, переходы через 0/5/10 °C, заморозки, роза ветров, опасные явления |
| **Прогноз** | 7 дней из Open-Meteo для района заповедника и сравнение со средним за те же даты |
| **Данные и отчёты** | Как прочитан каждый файл, флаги качества, полнота по годам, загрузка новых файлов, отчёты HTML и Excel |

Период выбирается переключателем «Месяц / Сезон / Год / Период» и мини-календарём; состояние экрана
хранится в адресной строке — ссылкой можно поделиться.

## Правила задания и как они выполнены

| Правило | Где в коде | Проверка |
|---|---|---|
| Флаг `параметр:причина` исключает только этот параметр; `dup_conflict` — всю строку | `meteo/loader.py` | у давления Кр1 за 2024 год исключено ровно 1 362 значения, как в README кейса |
| Сутки полные: АМЕ-60 — ≥ 72 из 96 сроков; Сокол М1 — ≥ 18 разных часов из 24 | `meteo/coverage.py` | **полное совпадение со всеми 420 строками `coverage_by_month.csv`** |
| Суточное среднее считается по всем валидным наблюдениям, включая несколько записей в одном часу. Средний и максимальный порывы считаются отдельно | `meteo/analytics.py: to_daily` | тест со смешанным шагом, флагом качества и выгрузкой в Excel |
| Полнота проверяется по каждому параметру отдельно | `meteo/analytics.py: to_daily` | давление Кр1 2024: 334 дня и 11 месяцев, апрель не входит — как в описании кейса |
| Месяц валиден: ≤ 10 неполных дней и нет 5 подряд | `meteo/coverage.py: month_valid` | юнит-тест на границы правила |
| Год — только при 12 валидных месяцах | `meteo/analytics.py: aggregate` | годовые средние АМЕ-60 считаются ровно за 1993, 2004, 2005, 2009, 2010, 2014, 2015, 2016 |
| Декады 1–10, 11–20, 21–конец | `meteo/tables.py` | таблицы и Excel учитывают границы выбранных дат |
| «Среднее за выбранный период» с фактическим числом лет | графики, выводы, отчёты HTML и Excel | годы задаются в настройках. Для каждой даты и каждого месяца число лет определяется отдельно |
| АМЕ-60 и Сокол М1 не объединяются, тренды через 2021/2022 не строятся | станции — отдельные ряды | сравнение станций работает только по общим дням |
| Время — как записано, без округления и сдвига | `meteo/loader.py` | — |
| Пропуски не заполняются, значения не исправляются | — | наши дополнительные проверки (выбросы, «залипание») только подсказки |

Все проверки — в `tests/test_case_rules.py` и выполняются на реальных данных кейса.

### Проверка измерений и демонстрационный сценарий

В «Обзоре» выберите АМЕ-60, «Температура воздуха» и период 01.01.2005–31.12.2015.
«Таблицы» показывают месячные значения и блок «Проверка месячных расчётов»: сколько исходных
значений участвовало в каждом расчёте, сколько исключено при импорте, на уровне суток и месяца,
сколько дней было полными. Строки с флагами можно проверить до отдельной отметки времени и файла.
Пустые сроки видны по числу полных дней, они не считаются исключёнными измерениями.

- Контекстная проверка использует длительность непрерывной серии, медианы и разброс соседних
  наблюдений, изменения других датчиков и сезон. Весной и осенью устойчивый сдвиг рассматривается
  как возможное погодное событие. Изолированный всплеск с возвратом и сдвиг между двумя почти
  ровными участками требуют проверки. Разрывы наблюдений прерывают серии. Штиль и близкая к
  насыщению влажность могут быть устойчивыми естественно. Эти правила выставляют приоритет проверки.
- Исключения по флагам источника, конфликтам и заглушкам учитываются отдельно. Контекстные
  предупреждения сохраняют значение для расчёта до подтверждения ошибки.
- Excel содержит «Важные аномалии», «Параметры выборки», «Проверка расчёта» и при наличии
  исключений «Исключённые измерения». «Важные аномалии» объединяют подтверждённые исключения в
  эпизоды и показывают приоритетные предупреждения с контекстом.
- Пентады и климадиаграмма на слайде 8 иллюстрируют форматы Летописи природы. Для приложенного
  набора действуют правила суточных и декадных таблиц из PDF. Осадки и радиация отсутствуют
  в согласованном архиве. Высота установки датчиков в архиве не указана.

## Дополнительные задачи

- **Сокол М1** — все таблицы и графики работают для Кр1 и Кр2 так же, как для АМЕ-60.
- **Поляна против поля за 2025 год** — экран «Поляна и поле»: разница по валидным месяцам и средний
  суточный ход по общим полным дням. При расчёте среднего для каждого часа все дни имеют одинаковый вес.
- **Давление Сокол М1** — обычный параметр на всех экранах; апрель 2024 у Кр1 исключён по правилу.
  Сравнение станций дополнительно находит февраль и март 2024 года: давление Кр1 на 13 и 40 гПа выше,
  чем на Кр2, при обычной разнице около 1 гПа — значения в допустимом диапазоне и флагом не отмечены,
  но это похоже на сбой датчика.
- **Прогноз** — Open-Meteo, без ключа, кэш на час (`meteo/forecast.py`).
- **Новый файл без доработки кода** — «Данные и отчёты» → «Добавить файлы». Станция определяется по
  имени: `kr1_2026.csv` допишется в ряд «Кр1 (поляна)», `ame60_2022.csv` — в «АМЕ-60», файл другой
  станции появится как новая станция. Пакет файлов применяется после проверки целиком. Сохранённые CSV,
  TXT и XLSX из `data/clgz/uploads/` подхватываются при перезапуске.

## Устройство

```
meteo/
  loader.py      чтение CSV/Excel, флаги качества, станция по имени файла
  coverage.py    правила полноты суток и месяцев
  analytics.py   агрегация, статистика, аномалии, тренды, суточный ход, сравнение станций
  tables.py      суточные и декадные таблицы, выгрузка в Excel
  insights.py    текстовые выводы
  views.py       ответы для экранов
  api.py         HTTP API (FastAPI) и раздача интерфейса
  forecast.py    прогноз Open-Meteo
  report.py      отчёты HTML и Excel
  batch.py       пакетная обработка из командной строки
web/             интерфейс без сборки: index.html, styles.css, app.js (графики — Plotly.js)
data/clgz/       данные кейса
tests/           тесты (в т. ч. на реальных данных кейса)
deploy/          деплой в Yandex Cloud
```

Данные держатся в памяти процесса — сервер запускается с одним воркером.
