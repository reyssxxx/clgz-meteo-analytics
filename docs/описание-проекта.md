# Метеоаналитика заповедника: шпаргалка для защиты

Кейс 02 «Умная аналитика метеоданных», Центрально-Лесной заповедник.
Сервис: https://d5dkpakcg8vs37s6pqe8.bu9mdbe1.apigw.yandexcloud.net/ (на ВМ в Yandex Cloud, перед ней API Gateway).
Код: https://github.com/reyssxxx/clgz-meteo-analytics

## 1. Одной фразой

Специалист выбирает станцию, параметр и период, а сервис сам считает по правилам задания, строит таблицы и графики
и показывает, что вошло в расчёт и что исключено. Раньше это собиралось вручную в Excel.

## 2. Боль и что её закрывает

| Боль специалиста | Что в сервисе |
|---|---|
| Сводки собираются в Excel вручную, каждый период заново | Любой период (месяц, сезон, год, свои даты) считается сразу. Таблицы и отчёты скачиваются |
| Не видно, что вошло в расчёт | Блок «Проверка месячных расчётов»: сколько значений вошло, сколько исключено и почему, до отметки времени и файла |
| Пропуски и сбои датчиков ищут глазами | Полнота по годам и месяцам, список подозрительных значений, автоматическая проверка «поляна против поля» |
| Приборы легко перепутать | АМЕ-60 и Сокол М1 хранятся отдельно, ряды не склеиваются, тренды через границу 2021/2022 не строятся |
| Новый файл с метеостанции | Загрузка файла без доработки кода: станция определяется по имени |

## 3. Данные

- **АМЕ-60** (урочище Красное): 805 489 строк, шаг 15 минут, 1992–2021. Параметры: температура, влажность, ветер, порывы, направление, температура почвы на 5/10/20 см.
- **Сокол М1**: 68 999 строк, шаг 30–60 минут, 2022–2025. Две точки: **Кр1 (поляна)** и **Кр2 (поле)**. Есть давление.
- Всего 874 488 строк. Приборы разные, общего периода работы нет.
- Правила из задания реализованы в `meteo/coverage.py`. **Наши 420 строк месячной полноты полностью совпали с `coverage_by_month.csv` организаторов.**

## 4. Два режима: гость и сотрудник

- **Главная `/`**: «Библиотека данных» (Метеоданные, Лошади Пржевальского, Цифровые летописи природы; последние два пока заглушки).
- **Гость** (без входа). Начинает с пустого набора. Добавляет открытые станции NOAA (Нью-Йорк, Бостон) или оставляет запрос на данные другой организации. После добавления станции доступна вся аналитика, но по этим станциям. Данные заповедника гостю недоступны. Загрузка файлов и восстановление пропусков закрыты.
- **Сотрудник** (вход по логину и паролю). Видит данные заповедника: АМЕ-60, Кр1, Кр2. Может загружать файлы, сопоставлять колонки, восстанавливать пропуски, добавлять открытые станции. В кабинете видит заявки гостей.
- Наборы гостей лежат в памяти сервера и изолированы друг от друга (cookie). После перезапуска сервера пропадают.

## 5. Общее управление вверху

Станция, параметр, период. Период: **Месяц / Сезон / Год / Период** (мини-календарь). Состояние хранится в адресной строке, ссылкой можно поделиться. Набор элементов на каждой странице свой.
Пункт «Среднее за выбранный период (N лет)»: это **не «климатическая норма»**, годы задаёт пользователь. Эту формулировку требует задание.

## 6. Страницы

### Обзор
- **График выбранного периода на фоне всех лет станции.** Цветная линия: выбранный период. Серые линии: тот же период в другие годы. Пунктир: среднее за выбранный период. Переключатель «Значения / Отклонения». Для сумм (осадки) график нарастающим итогом.
- **Тепловая карта отклонений**: месяц к среднему за выбранные годы. Видно, какие месяцы были теплее или холоднее.
- **«Почему выделены аномалии»**: текстовое объяснение выделенных значений (от Даши).
- **Место периода среди тех же периодов других лет** (столбики по годам). Пример для демо: лето 2010 теплее среднего на 3,6 °C, 1-е место из 22 лет.
- **«Коротко»**: выводы текстом. Они считаются по данным, нейросеть не используется.
- Кнопки: скачать график, «Отчёт HTML», «Таблицы Excel».

### Таблицы
- **Суточная таблица за месяц**: сроки по каждым суткам, неполные сутки помечены, итоги по декадам, за месяц, экстремумы.
- **Декадная таблица** за сезон, год или любой период. Декады: 1–10, 11–20, 21–конец.
- Сортировка, фильтр, сворачиваемые месяцы. Выгрузка в Excel в том же виде.
- **«Проверка месячных расчётов»**: сколько значений участвовало, сколько исключено при импорте, на уровне суток и месяца.

### Тренды
- **Полосы потепления**: отклонение годовой температуры от среднего за выбранные годы.
- **Тренд по году, сезону или месяцу**: среднее за каждый год, пунктир это линейный тренд.
- **«Как меняется климат»**: статистика ряда: МНК, тест Манна–Кендалла, оценка Сена. Только внутри ряда одной станции.

### Сравнение
- **Два любых периода A и B**: годовой ход по месяцам и таблица разницы с проверкой значимости.

### Метеостанции (Кр1 против Кр2 или любые две станции)
- Разница по месяцам или по дням (столбики разницы).
- **Средний суточный ход по часам** по общим полным дням. У каждого часа дни имеют одинаковый вес.
- Автоматическое предупреждение о вероятном сбое датчика. Пример для демо: **давление Кр1 в феврале 2024 на 13 гПа, в марте на 40 гПа выше, чем на Кр2** (обычная разница около 1 гПа). Значения в допустимом диапазоне и флагом не отмечены, обычная проверка этого не ловит.
- Таблица по дням или месяцам.

### Агроклимат
- Суммы температур (активных и эффективных), переходы через 0, 5 и 10 °C, последний весенний и первый осенний заморозок.
- График выбранного показателя по годам, выпадающий список показателей.
- **Роза ветров** (повторяемость направлений, штиль).
- **Опасные и неблагоприятные явления** по периоду.
- Таблица показателей по годам.

### Прогноз
- 7 дней из Open-Meteo для района заповедника, без ключа, кэш на час.
- Температура воздуха по часам и сравнение со средним за те же даты. График ветра.
- Рекомендации на основе данных (текстовые блоки, от Даши).

### Данные и отчёты
- **Наборы данных** и добавление: для гостя каталог открытых станций NOAA и форма запроса данных. Для сотрудника ещё загрузка файлов.
- **Отчёты**: HTML и Excel по выбранным станции и периоду. Все станции сразу из командной строки: `python -m meteo.batch`.
- **Полнота данных** по годам и месяцам, разбор файлов, флаги качества.
- **Дополнительная проверка**: подозрительные значения (выбросы, «залипание»). Это подсказки, данные они не меняют.
- **Сопоставление колонок** (сотрудник): что за колонка в файле, применяется к набору.
- **Восстановление пропусков** (сотрудник): значения из Летописи природы или по соседней станции. Хранятся **отдельным рядом**, в официальный расчёт не попадают. Для станции-образца проверка на удержанных годах, пороги пилотные.
- **Форма запроса данных** у другой организации (организация, станция, показатели, период, почта). Заявка сохраняется и видна сотруднику в кабинете.

## 7. Ключевые правила из задания (что говорить жюри)

- Флаг `параметр:причина` исключает только этот параметр, `dup_conflict` убирает всю строку.
- Сутки полные: АМЕ-60 не менее 72 из 96 сроков, Сокол М1 не менее 18 разных часов из 24. Проверяется по каждому параметру отдельно.
- Месяц валиден: не больше 10 неполных дней и нет 5 подряд. Год только при 12 валидных месяцах.
- Пропуски не заполняются, значения не правятся. Время как записано, без сдвига.
- Подтверждения: давление Кр1 за 2024 год исключено ровно 1 362 значения, 334 полных дня и 11 месяцев, апрель не входит. Годовые средние АМЕ-60 считаются за 8 лет: 1993, 2004, 2005, 2009, 2010, 2014, 2015, 2016.
- Все проверки в `tests/` на реальных данных, 78 тестов проходят.

## 9. Вероятные вопросы и честные ответы

- **Это нейросеть?** Нет. Выводы текстом формируются правилами по расчёту. Так результат воспроизводим и проверяем.
- **Почему не склеили АМЕ-60 и Сокол М1?** Приборы разные, общего периода работы нет, по заданию их ряды не объединяются.
- **Почему не заполняете пропуски?** Задание запрещает заполнять их в официальном расчёте. Восстановление ведётся отдельным рядом и помечено.
- **Что с осадками и радиацией?** Их нет в согласованном архиве. Высота установки датчиков в архиве не указана.
- **Где данные хранятся?** В памяти процесса, один воркер. Загруженные файлы сотрудника сохраняются на диск контейнера. Наборы гостей и заявки при обновлении сервера сбрасываются.
- **Безопасность?** HTTPS через API Gateway. Вход сотрудника по логину и паролю. Гость не может читать данные заповедника (сервер отвечает 403).
- **Масштабирование?** Демонстрационная версия на одной ВМ (2 vCPU 50%, 4 ГБ). Для продакшена нужны база и хранилище.
- **Что дальше?** Импорт архивных таблиц Летописи природы с проверкой страниц первоисточника, метаданные приборов и площадок, модели восстановления для влажности, ветра и осадков, интервью со специалистами заповедника.
